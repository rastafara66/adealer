# Попередній запис на обслуговування

Запис клієнта на СТО ДО того, як зʼявиться наряд — дзеркалить 1С-регістр
«ПредварительнаяЗапись» (УТП).

## Що це

Окрема сутність (не наряд і не замовлення): «клієнт записаний на такий-то пост,
такого-то дня/часу, до такого механіка». Наряд у ланцюзі документів зʼявляється пізніше —
запис може бути привʼязаний до замовлення клієнта, а може й ні.

## Моделі

- **`adealer.service.booking`** — сам запис. Поля:
  - `appointment_datetime` — дата/час запису (зберігається UTC, показ у TZ користувача).
  - `workplace_id` → `adealer.workplace` — пост (робоче місце).
  - `employee_id` → `hr.employee` — механік.
  - `advisor_id` → `hr.employee` — майстер-приймальник (МП).
  - `work_duration` (год), `intake_time` (Char) — час прийому а/м.
  - `sale_order_id` → `sale.order` — Заказ (замовлення клієнта, якщо повʼязаний).
  - `repair_order_id` → `repair.order` — наряд (кнопка «Створити наряд»).
  - `partner_id`, `vehicle_id`, `model_id`, `year`, `plate`, `phone`, `vin`, `requested_works`,
    `repair_type_id` → `adealer.repair.type`, `state`, `guid_1c` (ключ дедуплікації).
- **`adealer.workplace`** — довідник постів (Пост 1, Інтерактивний пост…).
- **`adealer.repair.type`** — довідник видів ремонту (є ознака `is_warranty` — гарантійний).

## Вигляди / де знайти

Меню **Обслуговування та ремонт → Попередні записи** відкриває **дошку по постах**:
- **Дошка по постах** (`adealer_booking_board`, OWL) — колонки = пости, події за часом+тривалістю,
  як розклад у 1С. Навігація по днях, перемикач **[По постах] / [По періодах]**.
- **По періодах** → стандартний календар (`action_service_bookings`).
- Список / форма — звичайні. Форма показує всі реквізити + держномер/роботи/механік.
- Довідники «Робочі місця / пости» та «Види ремонту» — у Налаштуваннях.
